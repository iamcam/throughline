# Phase 17 — Chat Response Streaming

## What was built
- `src/llm/base.py` — `ToolCallDelta` and `StreamChunk` dataclasses; `LLMClient.stream()` added to the Protocol as a plain `def` returning `AsyncIterator[StreamChunk]` (async-generator-returning callables are declared as plain `def`, not `async def`, at the Protocol level).
- `src/llm/client.py` — `OpenAICompatibleLLMClient.stream()`, calling `chat.completions.create(..., stream=True)` and yielding one `StreamChunk` per delta. Only reads `delta.content`; never reads `delta.reasoning_content`, so thinking-model reasoning text is dropped at the source and never reaches the accumulator.
- `src/query/stream_accumulator.py` — new module, `StreamAccumulator.accumulate()`. Joins content deltas and yields them live as `str`; reconstructs tool calls by `index` from `ToolCallDelta` fragments; yields exactly one terminal `LLMResponse` per round. Raises `MixedStreamResponseError` if a round mixes content and tool-call deltas out of order — fail-fast, no retry (retry would require buffering, defeating live token forwarding).
- `src/query/async_utils.py` — new module, `with_heartbeat()`. Races the source iterator's `__anext__()` against `asyncio.wait(timeout=...)`; yields `None` on timeout without abandoning the pending task, yields real items transparently.
- `src/query/engine.py` — `StatusEvent`, `TokenEvent(delta)`, `DoneEvent(citations, session_id)`; `QueryEngine.chat_stream()` (new) drives the full tool-round loop via `_stream_round()` (wraps `with_heartbeat(accumulate(llm.stream(...)), STATUS_HEARTBEAT_SECONDS)`, enforces `LLM_REQUEST_TIMEOUT_SECONDS`); `chat()` is now a thin wrapper that drains `chat_stream()` and assembles the same `ChatResponse` it always returned — single code path for both streaming and non-streaming callers.
- `src/api/routers/chat.py` — `POST /{session_id}/message/stream` (SSE via `EventSourceResponse`); `_sse_event_stream()` translates `StatusEvent`/`TokenEvent`/`DoneEvent` into `status`/`token`/`done` SSE events; `_error_type()` maps exceptions to stable string categories (`session_not_found`, `timeout`, `internal_error`) instead of exposing raw Python exception class names to the frontend.
- `src/api/dependencies.py` — fixed `get_query_rewriter()`, `get_retriever()`, and `get_embedder()` bare-calling their dependencies instead of using `Depends()` (silently bypassed `app.dependency_overrides` in tests); reordered file so `get_vector_store()` is defined before `get_retriever()` references it as a `Depends()` default (default parameter values evaluate at def-time, not call-time). Every helper in the file now follows the same `Depends()`-injection convention consistently.
- `backend/scripts/bootstrap.sh` — enables the `vector` extension on the `_test` database (previously only the main DB got it, via Alembic; the test DB is created via `Base.metadata.create_all()`, which doesn't run extension DDL).
- `frontend/src/api/client.ts` — `parseSSEStream()` (generic SSE line parser over `fetch()`'s `ReadableStream`, chat-agnostic) and `streamChatMessage()` (chat-specific, dispatches to `ChatStreamHandlers`: `onToken`, `onDone`, `onError`). Manual parsing required because `EventSource` only supports GET, and this endpoint needs a POST body.
- `frontend/src/components/ChatInterface.tsx` — `handleSend()` rewritten around one mutable assistant message object (stable `id`, created up front with `isThinking: true`) updated in place via `onToken`/`onDone`/`onError`, replacing the old thinking-placeholder-then-swap pattern. Error copy keyed off the new stable `errorType` strings; `resetSession()` still triggers on `session_not_found`.
- Tests: `tests/unit/test_stream_accumulator.py`, `tests/unit/test_async_utils.py` (new); `tests/unit/test_engine.py` migrated to `MockLLMClient(stream_chunks=...)`; `tests/integration/test_chat_streaming.py` (new — first SSE integration test in the codebase, with a hand-rolled `_parse_sse()` helper).

## Decisions made
- **Consolidated status events, not granular per-tool labels.** SSE emits a bare `status` heartbeat (`{}`, no payload) during tool rounds rather than naming which tool is running — avoids coupling the frontend to the backend's tool set. The existing "Thinking" indicator already covers this; it just persists until the first `token` event instead of until the whole response arrives.
- **`chat()` as a thin wrapper over `chat_stream()`**, not two parallel implementations. Required migrating every existing engine test from `MockLLMClient(responses=...)` to `stream_chunks=...`, but was judged worth it to avoid duplicating the tool-round/synthesis-fallback/session-mutation logic in two places.
- **Whitespace-only content deltas do not count as "content happened."** Discovered live: Qwen 3.5 (thinking mode, via MLX) emits a `content` delta of `"\n\n"` as a formatting artifact between its `reasoning_content` block and its `tool_calls` deltas. A naive truthiness check (`if chunk.content_delta:`) treated that as real content and tripped `MixedStreamResponseError`. Fixed by gating on `chunk.content_delta.strip()` instead — a whitespace-only delta is neither yielded as a token nor counted toward `saw_content`, while genuine internal whitespace inside real content (e.g. a paragraph break within an actual answer) still passes through unchanged.
- **`reasoning_content` is dropped entirely, unconditionally**, not surfaced anywhere. `OpenAICompatibleLLMClient.stream()` only ever reads `delta.content`; thinking-model reasoning text never becomes a `StreamChunk` in the first place. No UI, no logging, no capture — a deliberate simplification given the product decision that tool/thinking activity should never be shown as anything more than the generic status heartbeat.
- **Heartbeat via `asyncio.wait()` race, not a fixed poll loop.** `with_heartbeat()` never abandons the in-flight upstream call while ticking — a slow single LLM call still completes normally once it finishes, heartbeats are purely a wait-time indicator layered on top.

## Known issues / tech debt noted
- `_error_type()` only distinguishes `ValueError` → `session_not_found` and `LLMTimeoutError` → `timeout`; everything else collapses to `internal_error`. Fine today, but will need expansion if/when new user-facing failure modes are introduced (e.g. a distinct rate-limit error).
- No mechanism captures or surfaces `reasoning_content` even for debugging/observability purposes — if thinking-model reasoning ever becomes useful to inspect (e.g. in Phoenix traces), that's new work, not something this phase's plumbing already supports.

## Done-when criteria
- `POST /{session_id}/message/stream` streams `status` → `token`* → `done` (or `error`) over SSE, matching `[query] → [status/thinking] → [streaming tokens]`.
- The frontend shows "Thinking" from send until the first token, then renders tokens incrementally into a single message bubble, with citations attached once `done` arrives.
- A tool-calling round against a real thinking-model backend (Qwen 3.5 via MLX) completes without raising `MixedStreamResponseError`, verified against real reasoning_content + whitespace-content-then-tool_calls chunk sequences.
- `chat()` (non-streaming) behavior is unchanged from pre-Phase-17 for all existing callers/tests.
- Full unit + integration suite green; manual end-to-end verification done in the browser.
